# 开发顺序、验收与缺口

本文件用于约束另一个 AI 的交付。先做一个能完整说明产品的首页，不以大批空页面或装饰动画代替核心交互。

## 1. 实施阶段

### 阶段 A：建立可预览页面与稳定资源路径

读取全部设计文档、媒体清单和参考图。若在当前工程内开发，先确认 `website/package.json`、静态服务和已有页面路径，保持 HTML/CSS/ES Modules 架构，不擅自重建；若是独立空目录，采用技术文档给出的轻量静态工程方案。

建立导航、Hero、能力主舞台、精简下半页、页脚及 `/demo/` 最小页面；先用真实海报占位。三任务切换、导航锚点与预约跳页先可操作。Hero 纯背景缺失应列为明确缺项，不阻塞其他部分实现。

验收：320 px 与 1440 px 下结构都可读；核心按钮有效；无横向溢出、无死链；视频资源为包内路径，不引用开发者电脑的绝对路径。

### 阶段 B：先完成行业场景纵向闭环

先对行业视频有效短段完成逐帧观察、目标与路面区域校准；将结果写入统一契约。实现“车辆检测／区域进入”两预设、六节点链、原始／分析／对照和事件回放。所有状态从媒体时间推导。

如果没有有效区外到区内的证据，不能伪造事件；应先修正预设区域或调整演示片段。未校准状态不能为了“看起来完成”输出随机方框。该阶段通过再扩展其他两个任务。

验收：暂停、重播、快进、倒退、改尺寸都不漂移；事件只在有效条件下出现；只检测模式不产生区域事件。

### 阶段 C：自然语言与以图搜图

根据分镜选取有效短段。自然语言先支持一个明示预设；以图搜图先支持一个清晰参考图。实际制作参考图和轨迹时保持媒体来源一致；不同车辆／不同人不能共享假连续身份。

验收：三任务在视觉和行为上可区分；快速切换不残留另一任务的目标和结果；无需输入任意文本／上传任意文件就能体验能力；未提供的自由输入能力清楚限制。

### 阶段 D：手机与动效精修

完成手机全画幅、操作外移、阶段摘要与完整链展开、目标局部查看。实现 Robotfolk 启发的同帧分析层显现、对照滑杆、节点与结果联动；减少动态模式与键盘体验同步完成。

验收：下面测试矩阵全部覆盖；避免只展示一张漂亮桌面截图。页面滚动始终自然可控。

### 阶段 E：资源优化与交付

为大视频另存网页播放版本，保留原件、比例和时间映射。完善媒体加载失败、自动播放失败、离屏暂停。输出启动方式、页面地址、实际测试证据、未完成项及后续 API 接入说明。

除非用户另有明确要求，不部署、不购买模板、不提交真实预约、不上传视频给第三方服务。

## 2. 核心验收用例

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| H01 | 进入首页 | 品牌、理念正确；可在首屏找到能力入口；没有占屏长文 |
| H02 | 点击三个任务标签 | 顺序正确，视频不同；旧播放与分析数据清理；当前任务名与素材一致 |
| H03 | 切行业预设 | 检测与区域进入的链和结果确有差异；没有只换按钮颜色 |
| H04 | 观察已校准目标段 | 框贴合目标，不换对象；遮挡／出画隐藏；区域随地面透视而变 |
| H05 | 暂停、缓冲、后台切回 | 画面时间、框、区域、节点和结果不各自继续运行 |
| H06 | 拖动至事件前后并反复回放 | 状态可从任意时间重建；无事件重复弹出、无旧结果堆积 |
| H07 | 原始／分析／对照 | 同一视频同一时刻；分隔线只遮盖分析层；拖动流畅且可键盘操作 |
| H08 | 点击算法链节点 | 显示简短用途；任务改变后说明同步；不会展开后台工作台 |
| H09 | 自然语言演示 | 预设词与可见骑行者对应；没有对任意文本假返回结果 |
| H10 | 以图搜图演示 | 参考图与候选外观可辨；不把白色 SUV 与白色轿车当成同一目标 |
| H11 | 点击结果／查看片段 | 对应正确视频、对象、时间；暂停态细节来自当前源，不来自另一支媒体 |
| H12 | 反复快速切换任务 | 最后一次选择生效；无未处理异常、媒体回调泄漏和后台并行播放 |
| H13 | 页面窄至 320 px | 主体不裁掉，标签可读、控件可点，算法链可展开，整页不横向滚动 |
| H14 | 转屏、200% 缩放 | 不丢用户状态；重算视频映射；导航与控制可见 |
| H15 | 减少动态模式 | 默认静态／手动播放；无自动扫描、视差；功能不缺失 |
| H16 | 键盘完整操作 | 可以换标签、播放、暂停、拖动对照、查看结果、关闭菜单与预约跳页 |
| H17 | 模拟媒体 404／断网／播放拒绝 | 保留封面、错误与重试；页面其余部分正常；不无限假加载 |
| H18 | 点击预约 | 到独立页面；只有公司、联系方式；静态版不显示已提交或已送达 |
| H19 | 首次加载查看网络请求 | 不同时下载三支完整视频；不依赖本机绝对路径或未授权远程热链 |
| H20 | 查看分析数据来源 | 功能演示标识可见；无虚构性能数字；真实后端模式与演示模式可区分 |
| H21 | 刷新独立预约路径 | 静态站路径可正确加载，返回首页有效；不是只有前端跳转可用 |

## 3. 视口与浏览器测试矩阵

- 布局截图：320×740、390×844、430×932、768×1024、1024×768、1366×768、1440×900、1920×1080、2560×1440。
- 补充：844×390 手机横屏；200% 页面缩放；较低高度的桌面窗口；`prefers-reduced-motion: reduce`。
- 核心交互至少在 390×844 与 1440×900 全量跑通，不要求每个尺寸重复完整功能用例。
- 浏览器至少检查 Chromium；再检查可用的 Firefox、WebKit。真实 iOS Safari 的视频内联与自动播放行为需要真机确认。未测某引擎／真机要明确记为未测，不能用模拟视口代替。
- 自动化报告记录实际尺寸、浏览器、媒体文件版本、交互状态和截图路径。测试通过后若换视频、改时间或改裁切，应重新检查相关输入。

## 4. 静态与接口边界验收

1. 内容、媒体、分析结果、预约操作各有明确数据提供层；页面组件不直接散落请求地址。
2. 切换到 `static-demo` 模式无需后端即可运行；任意输入、用户上传和真实预约提交默认不可用。
3. 准备一个映射适配器接口即可接入后端；演示 JSON 不强迫后端改成相同内部存储结构。
4. 媒体 ID、哈希、时间、坐标系和结果来源共同决定能否渲染；不同版本的数据不能静默混用。
5. 传入的文本按文本渲染；不把结果字段作为任意 HTML 注入。静态配置不包含 API key、私密 token 或个人联系方式。
6. 静态服务支持实际视频 Content-Type，需检查 Range／断点请求；文件与媒体配置可跟随基础路径部署。
7. 预约服务未配置时返回 `unavailable`；只有真实接口返回接收凭证才呈现已收到。

## 5. 已知缺口与处理责任

| 缺口 | 本包状态 | 实现 AI 应执行的动作 | 是否可省略 |
| --- | --- | --- | --- |
| 已确认 Banner 的干净独立图 | 未找到；只有完整版式截图 | 留好挂载结构、明确缺项；用户提供后替换；不偷偷换场景 | 最终 Hero 视觉验收不可省略 |
| 三支片段跟踪坐标／ROI | 未完成逐帧标注；契约中明确待校准 | 对实际片段标注、插值、逐帧复核 | 核心分析演示不可省略 |
| 白车参考小图 | 未另存 | 从最终有效片段提取，保存帧时刻和来源 | 以图搜图演示不可省略 |
| 网页压缩视频 | 未制作；提供原件 | 另存派生文件，检查目标清晰度和时间轴 | 本地可先用原件；交付性能不可忽略 |
| 真实分析后端 | 未接入 | 使用静态提供层，保留适配接口 | 本期不开发 |
| 真实预约接收渠道 | 未配置 | 独立页面展示字段和静态状态，不假提交 | 本期不发送 |
| 实际网页与移动端测试 | 本轮未开发／未测试 | 完成页面后按矩阵执行 | 页面交付不可省略 |

## 6. 实现 AI 最终应交付

可启动的静态工程；实际可访问的本地预览地址；媒体与数据文件；启动和构建命令；所有核心交互的说明；桌面与手机截图或录屏；已执行与未执行的验收记录；待补素材清单；后端接入时要替换的文件／接口说明。

不要只交一张整页图片、只画按钮但不实现、只列计划、只做桌面，或把“技术点”全部写成一大段介绍文字。
