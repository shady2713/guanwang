## 2. 四条分析标注数据的一致性校验结论

校验规则来自 `src/contracts/validation.ts`，在浏览器运行时真实执行（每次加载分析文档都会跑一遍）。

### 2.1 媒体绑定

| 分析文件 | 预设 | binding.mediaId | 清单 sha256（前 8 位） | 编码尺寸 | 时长 | timebase | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `data/analysis/industry-region-entry.json` | `region-entry` | `industry-v1` | `75a14723` | 1264×640 | 10s | `presentation-seconds` | 一致 |
| `data/analysis/industry-vehicle-detection.json` | `vehicle-detection` | `industry-v1` | `75a14723` | 1264×640 | 10s | `presentation-seconds` | 一致 |
| `data/analysis/language-find-cyclist.json` | `find-cyclist` | `language-v1` | `bbb4217a` | 1280×720 | 10s | `presentation-seconds` | 一致 |
| `data/analysis/image-similar-vehicle.json` | `similar-vehicle` | `image-v1` | `7c129e01` | 1216×672 | 10s | `presentation-seconds` | 一致 |

- 四份文档的 `binding.mediaId` 与 `preset-presentations.json` 中该预设声明的 `mediaId` 一致；`encodedWidth` / `encodedHeight` / `durationSec` / `timebase` 与 `media-manifest.json` 对应资产一致；`playbackWindow.endSec` 均未超过媒体时长（5.25 / 9.75 ≤ 10）。
- 表中列出的是前缀对照；**完整 sha256 的逐字符比对由运行时门禁完成**。该门禁在验收期间被真实触发过：`industry` 两份标注的 sha256 曾在录入时少一位字符，`validation.ts` 立即拒绝并给出「分析数据与媒体构建不一致：… 旧标注不能套用到新版本媒体。」，页面提示「…画面仍可观看，不显示分析标记。」；修正后恢复正常。这说明媒体绑定校验不是摆设。
- 另有一条播放窗口一致性校验：预设与分析文档的 `playbackWindow` 不一致时抛 `DataContractError('预设与分析数据的播放窗口不一致，已停用分析叠加层')`。四组数据当前一致。

- 全部轨段样本时间**严格递增**且完整落在各自 `interval` 内，没有超出边界的样本。
- 全部段的最大样本间隔都小于各自声明的 `maxInterpolationGapSec`，不存在「不能安全插值」的硬失败。

- 区域多边形的 `coordinateSpace` 均为 `encoded-frame-normalized`、顶点数为 4 且同一片段各样本一致；所有目标框宽高为正且 `x+w`、`y+h ≤ 1`。

| 项目 | 状态 | 原因 / 备注 |

| Safari、Firefox、Edge | 未验证 | 全部验收在 Chromium 上完成；`MediaError` 分支、`<video>` 行为、`IntersectionObserver` 阈值在不同内核下可能有差异 |
| 真实后端 / 预约提交 | 未验证 | `StaticLeadProvider` 为 `disabled` 模式，提交接口、鉴权、限流均未实现也未联调 |

| LCP / CLS / INP 等性能指标 | 未验证 | 没有实测。「首屏只加载一支视频」是设计约束（H19 已验证），不是性能结论 |

### 5.1 验收过程中发现并修复的缺陷

以下是本轮浏览器实测**真实暴露**的问题，修复前均已复现，修复后重测通过：

| # | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 每次加载视频海报都不显示 | `posterUrl` 相对媒体文件解析成了 `http://…/media/media/posters/industry.jpg`；Vite 的 SPA 兜底让这个错误路径返回 200 + `index.html`，所以「看起来不报错」 | 改为对 `document.baseURI` 解析（`src/media/stage-controller.ts`） |
| 2 | 媒体失败后点重试，卡在「正在准备演示画面…」 | `retry()` 先调 `video.load()` 再赋同一个 `src`，资源选择被打断，元素停在 `readyState 0` 且不再发请求 | 先赋 `src` 再 `load()` |
| 3 | 页面上根本没有重试入口 | 错误态的封面按钮调用的是 `play()` | 错误态改为调用 `controller.retry()`，文案变「重试加载演示画面」 |
| 4 | 从其它标签切回「行业场景」时预设切换器消失，停在「该任务的演示数据尚未提供」 | `defaultPresetFor()` 返回了上一个场景遗留的 presetId，匹配不到任何预设就提前返回 | 外来 presetId 回落为 `region-entry` |
| 5 | 切标签时同一支视频被重复请求多次 | 舞台骨架先按 presentation 加载一次，分析文档到达后又按 analysis 的窗口加载一次 | `load()` 增加「同源同窗口且非错误态则直接返回」的短路；实测切标签的 `src` 赋值次数由 2 次降为 1 次（`loadcount.mjs`） |

## 7. 接入真实后端需要替换的文件

只有第一行是必须改的；其余是配套项。**所有数据仍然走 `src/contracts/validation.ts` 的同一套门禁。**

| 文件 | 当前实现 | 接入后端时要做什么 |
| --- | --- | --- |
| `src/providers/static-providers.ts` | `StaticContentProvider` / `StaticContentBundle` / `StaticMediaProvider` / `StaticAnalysisProvider` / `StaticLeadProvider` 全部用 `fetch` 读本地 JSON | 逐个换成真实服务实现，**保持现有方法签名与返回形状不变**：`getHome()` / `getPresets()` / `load()` / `peekChains()` / `getMedia(mediaId)` / `getPreset(selection)` / `submit(payload, context)`（返回 `{ status, message, receiptId? }`） |
| `src/config/app-config.ts` | `mode: "static-demo"`，`flags.arbitraryTextSearch` / `userImageUpload` / `leadSubmission` 全为 `false` | 按能力逐项改 `true`，**同时**在 UI 层实现对应分支；只改开关会把「不支持」藏起来 |
| `src/contracts/domain.ts`、`src/contracts/app-content.ts` | 数据契约类型 | 字段与后端返回对齐时只改类型，不改语义；新增字段时同步 `validation.ts` |
| `src/contracts/validation.ts` | 运行时数据门禁 | **建议原样保留**：媒体绑定（sha256 / 尺寸 / 时长 / timebase）、样本严格递增与插值上限、ROI 坐标空间、规则与事件的引用完整性。服务端返回的数据同样要过这一关 |
| `src/pages/capability-stage.ts` | 静态演示的预设切换、工具栏与结果渲染 | 只有在新增能力形态（例如真·任意文本查询、用户上传参考图）时才需要加分支 |

不需要改动的部分：`src/media/stage-controller.ts`、`src/render/stage-overlay.ts`、`src/render/viewport-mapper.ts`、`src/domain/*`、`src/styles/*`、`index.html`、`demo/index.html`、`vite.config.ts`。
