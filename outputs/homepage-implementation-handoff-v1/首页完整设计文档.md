## 先读结论

首页以可交互的视频分析舞台为核心：行业场景、自然语言、以图搜图三种任务各有独立视频；识别框、区域、轨迹、算法链和结果通过网页叠加。访客可以切换原始／分析／对照视图，以及行业检测／区域进入预设，理解算法链的价值。

先实现全静态数据提供层，后续由适配器接入真实后端；不把任意输入、真实识别或预约提交伪装为已接通。所有预约按钮跳独立页面。

响应式覆盖 320–2560 px；手机保留完整画幅、操作外移，算法链以阶段摘要加完整节点展开呈现。正文保持简短，科技感通过有因果关系的交互表现。

素材包含三支原始视频、真实抽帧封面和完整页面参考图。Banner 独立干净背景、逐帧跟踪标注、白车参考裁图仍需在实现阶段补齐。本套文档没有把未标定数据伪装成可上线结果。

## 视界 AIMaster · 首页设计规格

版本：1.0。日期：2026-10-09。目标：交给另一个 AI，实现可本地预览的静态首页；本轮交付设计与技术说明，不代表页面已经开发完成。

### 1. 唯一设计目标

让第一次接触产品的访客，在不阅读长篇技术介绍的情况下，看懂三件事：平台能从巡查影像中找到目标；能够结合配置条件形成事件；这些步骤可以组合成算法链，适配不同任务。

视觉基准是已确认的 v9 精简首页：明亮城市、白底、深蓝大标题、清晰蓝色交互，以及连续的大画面。交互以用户确认的 Robotfolk 为主要参考。它的机器视觉显现、原始画面与分析视图对照等表达，转译到真实业务演示中；不用机器人本身、家庭场景或其模板代码。

权威顺序：本次用户明确要求 → 本套文档 → v9 页面结构和用户确认的 Banner 构图 → 较早图稿。较早图稿里的冗长说明、并列结果卡、首页预约表单不再采用。遇到资料缺失要记录，不得用假指标或任意素材补成“已完成”。

### 4. 视觉规范

#### 4.1 颜色与表面

| 用途 | 建议值 | 使用方式 |
| --- | --- | --- |
| 主背景 | `#FFFFFF` | 保持页面连续；不把每段包进灰色大卡片 |
| 辅助背景 | `#F4F8FF` | 算法链底带、轻量结果区 |
| 主标题 | `#101A3A` | 大标题、重要结果 |
| 正文 | `#34445F` | 一句说明、节点详情 |
| 次级文字 | `#52647E` | 辅助操作、来源标识；白底下保证可读 |
| 品牌蓝 | `#0066FF` | 重点按钮、激活节点、目标框 |
| 深蓝按钮 | `#0052CC` | 需要白字的小尺寸按钮优先用此色 |
| 边界 | `#DCE6F3` | 分隔线与必要控件轮廓 |
| 成功状态 | `#087F5B` | 有文字／图标配合的完成状态 |
| 提醒状态 | `#9A5B00` | 待复核或素材说明，不制造红色警报墙 |

蓝色用于建立阅读顺序；青色只能作为短促的信号移动点，不做大面积荧光。视频上必要控件使用局部白色半透明底，复杂画面需实测对比度，不能靠非常浅的透明文字。

#### 4.2 字体、间距与边角

- 中文采用系统无衬线字体栈：PingFang SC、Microsoft YaHei、sans-serif；英文跟随系统字体。首版不依赖境外字体 CDN，也不下载大型中文全字库。
- Hero 标题桌面 56–72 px、行高 1.08–1.16；手机 34–40 px。品牌理念允许明确分成两行。
- 大章节标题桌面 36–44 px、手机 26–30 px；正文 16–18 px；常用控件 14–16 px；辅助文字最低 12 px，仅用于非关键备注。
- 主容器最大宽度 1440 px；文字段落限制在约 36–42 个汉字宽。首页不按整张设计图片等比缩放。
- 桌面段间留白 88–120 px；平板 64–80 px；手机 40–56 px。正文说明通常一行，最多两行。
- 舞台圆角 16 px，手机 10 px；按钮圆角 8 px。避免所有容器都用超大胶囊和厚阴影。
- 使用统一的成熟线性图标库或现有项目图标资产。技术标记是数据绘制的功能图形；不以随手绘制的图标代替正式品牌或产品图片。

### 5. 顶部导航

桌面为左品牌、中导航、右预约按钮。导航采用“产品能力、应用场景、部署与集成、资源与支持”；首页分别指向既定锚点。导航高 72 px，向下滚动后缩至 64 px，变化时间 220 ms。使用轻微模糊的浅色背景与细边界，不增加占屏的大下拉菜单。

手机导航高 60 px，显示品牌、预约按钮、菜单按钮。菜单点击展开为可关闭面板；菜单打开时管理焦点、允许 Esc 关闭，关闭后归还焦点。导航锚点跳转考虑固定导航高度，标题不能被遮住。菜单中同一时刻只显示必要的一级导航。

预约按钮始终进入 `/demo/`，不能改为弹窗或首页表单。若当前项目已经有预约页，保留既有路径与外观风格后适配本方案。

### 6. 城市首屏

#### 6.1 已确认的构图

沿用用户确认的湖面、中央门形高楼、右侧道路和右上方无人机。左侧为标题与主按钮。标题真实 HTML 排版；图中不能重复出现烧录的文字和导航。

桌面图像与文案同屏叠放，Hero 从导航下开始，高度建议 `clamp(520px, 72svh, 780px)`；短屏低于 700 px 高时改为自然内容高，避免按钮出屏。大图具有空间感，左侧只用必要的渐变提高字的可读性。

手机采取“文案在上、画面在下”，图像完整保留重要主体；不能居中裁切到门形楼或无人机消失。Hero 不承担播放三支业务视频之一。

#### 6.2 首屏动效

进入页面后标题在 480 ms 内显现，主按钮随后出现。若拥有已确认的独立 Hero 视频，按静音、内联、可暂停方式播放；无人机附近最多一条克制的巡航轨迹。视觉重点仍是原有城市画面。

Hero 与能力舞台之间通过留白、标题位置和一次轻微画面展开衔接。不要让滚动控制业务视频逐帧播放，也不锁住用户滚轮。手机取消视差、鼠标跟随和全屏长时间停驻。

#### 6.3 素材缺口与首版处理

本包只有已确认的完整网页参考截图，**没有同构图的独立干净 Banner 图片或 Hero 视频**。两张参考截图仅供对照，不可整张放进网站，也不可把其文字当成网页功能。

执行 AI 应先检查用户后续提供的同构图干净素材。若仍缺失，继续完成三视频主舞台和响应式结构，Hero 保留真实标题、按钮及图片挂载结构，采用明确列入交付缺项的浅色临时背景。不得悄悄换成另一座城市、重复行业视频、拉伸整页截图或声称 Hero 视觉已验收。补入正确图片只改资源配置，不改布局代码。

### 7. AIMasterflow：整站交互主舞台

#### 7.1 结构

一个主舞台，按顺序包含：标题 → 三个任务标签 → 当前任务操作栏 → 视频与叠加图层 → 播放／显示控制 → 算法链 → 单行价值说明。不要在同屏再放三个独立视频卡片。

桌面主舞台尽量占满内容宽度。视频优先完整显示原比例；三片比例不同，外框采用统一的约 2:1 展示区并用 `contain` 适配，剩余边缘用近白／深中性底承接。图层定位绑定真实视频内容矩形，不绑定包含留边的外框。手机完全按当前视频原比例显示，避免顶部底部的文字挤占画面。

#### 7.2 核心显示模式

| 模式 | 呈现 | 交互 |
| --- | --- | --- |
| 分析效果（默认） | 实景与已校准的区域、目标框、轨迹 | 可以点选目标或事件 |
| 原始画面 | 同一视频同一时间，不显示分析图层 | 用于理解差别，不重播视频 |
| 对照 | 同一视频上仅在分隔线一侧显示分析图层 | 拖动分隔线；键盘也能调整 |

对照只用一个视频播放器。分隔线裁切叠加层，而不是叠放两个各自播放的视频。操作栏、结果文本与功能演示标识不随分隔线被裁切。手机保留三模式，默认不显示拖动把手；进入“对照”才显示大尺寸把手和可访问的范围控件。切换观看模式本身保持播放状态；开始拖动把手时暂停，松手保持暂停，由用户点击播放恢复，方便仔细比较同一帧。

#### 7.3 行业场景：配置带来不同结果

默认选择“区域进入”，另有“车辆检测”预设。两者共享同一视频与已校准目标数据。

- 车辆检测：呈现目标框；简化链为“视频输入 → 抽帧处理 → 车辆检测 → 结果输出”。
- 区域进入：增加路面区域与跟踪，“视频输入 → 抽帧处理 → 车辆检测 → 目标跟踪 → 条件判断 → 事件输出”。
- 切换预设时，保持任务标签不变，暂停并回到该预设的开始位置；新增节点用 240 ms 渐显加入。没有设置延时假装真实算力计算。
- 在有效入区时刻出现一张短结果：“车辆进入指定区域”。按钮“查看片段”从事件前开始回放。结果不擅自上升为违法结论。

“条件判断”节点可点击，展开紧邻算法链的说明：关注区域、由外向内进入。首版区域为预设，不提供表面可拖但结果不随之变化的假编辑器。若以后开放编辑，条件和事件都必须重新计算。

#### 7.4 自然语言：描述目标，得到可定位结果

操作栏显示预设查询“查找骑行人员”，按钮“演示查找”。用户点击后播放对应可见片段，在合适时点显现骑行者标记和结果条。第一次进入可用一次简短输入显现演示提示，不循环打字、不反复清空用户操作。

静态版限定为已配置的查询样例。不能显示任意输入框却对所有内容返回相同结果。若保留可编辑输入，只接受已支持样例并在其他输入时清楚显示“当前演示支持：查找骑行人员”，不发起网络请求。

算法链说明这是文本条件参与匹配的一种任务方式；展示节点名称由产品配置提供，静态原型可用“画面输入 → 目标分析 → 文本条件匹配 → 结果输出”的概念链，并标明演示。不得暗示自然语言自动生成了任意复杂业务规则。

#### 7.5 以图搜图：参考目标与动态候选对应

操作栏显示一张预设白车参考图与“查找相似目标”按钮。参考图从本次选定的有效视频片段中导出，或由用户提供有明确来源的目标图；不能用另一辆不相似的车来假装同一目标。

演示启动后，视频继续移动，候选目标逐一显现；点击某个候选，可查看该时刻的局部。结果表述使用“外观相似目标”，不给未经计算的百分比、身份结论或车牌识别结果。

首版不必提供真实文件上传。若提供上传外观入口，点击应说明当前为样例演示；不要让用户选择个人图片后悄悄返回固定结果。

#### 7.6 算法链如何产生科技感

处理节点沿一条连线排列，激活节点有轻量蓝色描边和一次信号流动。运行状态只对应演示脚本，不展示虚假的服务器资源和吞吐量。

默认只显示节点名称与图标。点击节点后，在链下展开最多两行用途说明；所有节点详情共用一处空间，避免同时出现多个悬浮卡片。再点当前节点或关闭按钮收起。

当前任务只显示相关链；同一含义的输入、输出等节点复用同一组件和稳定 ID。用户切换行业预设时，能看见哪些步骤保留、哪些步骤加入。这比增加装饰性旋转图形更直接地说明核心能力。

#### 7.7 结果与证据

桌面事件发生后可在视频安全区短暂显示标题胶囊，主要结果放在舞台下的固定高度结果条；手机全部放到画面下方。避免持续占据路面和主体。

点击结果展开非模态详情，默认含“目标、判断条件、事件时间、关联片段”四类信息。时间是视频相对时间，如 `00:03.20`，不是伪造的现场时间。回放定位按同一视频和相同媒体版本执行。区域事件只有有效进入证据才显示；遮挡不能当作离开区域。

### 8. 小目标表达

保留 v9 的紧凑横向段落，而不是再开一个大产品模块。桌面左侧短标题与“查看分析流程”，右侧同一帧的全景和选中局部；手机上下排。

### 1. 布局断点

| 区间 | 典型宽度 | 页面边距 | 布局 |

| 紧凑手机 | 320–374 px | 16 px | 单列；长控件可换行；标题不溢出 |
| 常规手机 | 375–767 px | 20 px | 单列；三任务标签等分；控制条分两行 |

### 2. 关键组件逐端处理

| 组件 | 桌面 | 手机 |
| --- | --- | --- |

| 目标细节 | 点击目标后显示当前帧局部 | 由可访问的目标按钮进入当前帧局部，保留返回全景 |

手机三阶段摘要是导航摘要，不替换真实处理链。例如纯检测链没有条件判断阶段时，摘要改为“输入／识别／结果”；不要所有模式套上不存在的节点。

320 px 下控件不足时允许第二行，不能隐藏“暂停”“重播”或缩到难以点击。横屏手机按可用高度自然排版，不强制充满 `100vh`。使用安全区内边距，避免刘海与底部系统手势遮挡。

### 3. 动效设计清单

| 编号 | 动效／触发 | 时间与幅度 | 目的 | 手机／减少动态 |
| --- | --- | --- | --- | --- |
| M01 | 首屏标题出现 | 480 ms；透明度与 ≤12 px 位移 | 建立主次 | 手机 ≤8 px；减少动态直接显示 |
| M02 | 导航收紧 | 220 ms；高度 72→64 px | 保留空间 | 手机保持 60 px，不反复变化 |
| M03 | 能力舞台进入视口 | 420 ms；轻微显现，画幅最多 0.98→1 | 让视频成为视觉中心 | 手机仅显现；减少动态关闭 |
| M04 | 切换任务 | 160–220 ms 淡出／淡入，旧图层先清空 | 明确进入新任务 | 同行为；不沿用旧目标框 |
| M05 | 分析扫描 | 每次启动最多一次，500–700 ms；低透明度细带 | 提示开始分析演示 | 手机简化；减少动态不扫描 |
| M06 | 目标确认 | 140–180 ms 框角显现 | 让访客定位目标 | 不持续闪烁、不呼吸放大 |
| M07 | 算法链信号 | 220–360 ms 单次沿连线移动 | 对应处理步骤 | 手机摘要状态变化，展开后才显示细节 |
| M08 | 事件形成 | 180 ms 显现；区域轮廓短暂强调一次 | 对应条件触发 | 手机结果条更新，布局预留高度 |
| M09 | 对照拖动 | 随手移动，无额外弹性 | 比较同一画面的分析层 | 触控、键盘共用同一值 |
| M10 | 展开节点／结果 | 180–220 ms，不从远处飞入 | 按需解释 | 减少动态立即展开 |

默认 easing：`cubic-bezier(0.22, 1, 0.36, 1)` 用于进入；一般状态切换 `ease-out`。所有持续运动都可暂停。科技感来自画面与计算步骤的因果关系，而不是光圈数量。

首版不用强制滚动劫持、全页横滑、持续追鼠标粒子、随机跳动数据、3D 地球、满屏网格或重型 WebGL 背景。主舞台内的目标框跟随视频已经提供足够动态。首版不锁定 GSAP、Three.js 或某商业模板。

### 4. 主舞台状态机

展示状态与播放状态分开保存，避免一个 `isPlaying` 管理所有情况。

| 状态 | 可见反馈 | 用户能做什么 |
| --- | --- | --- |
| poster | 封面、任务名、播放按钮 | 播放、换任务 |
| loading | 保持封面与占位尺寸，显示加载状态 | 换任务、取消；不显示假分析进度 |
| ready / paused | 正确时间对应的画面和标记 | 播放、换视图、选择节点、定位时间 |
| playing | 视频、图层与脚本同步 | 暂停、拖动进度、看结果 |
| seeking | 标记暂时隐藏或等待当前帧稳定 | 完成后恢复对应时刻，不播放旧事件动画 |
| buffering | 停住当前帧与时间状态，轻量提示 | 等待、重试或换任务 |
| ended | 保留最终有效结果；显示重播 | 重播、查看片段、切换任务 |
| error | 封面、明确错误与重试 | 重试、换任务；基础文案仍可读 |
| no-tracking | 视频可播放，提示分析标记待配置 | 看原始画面；不得画随机框冒充完成 |

默认进入页面不下载三支完整视频。主舞台接近视口时，加载默认片段所需资源。自动播放只在允许的桌面环境作为增强；初次加载需静音、内联且捕获播放失败。手机优先封面＋明确播放按钮。无论何种环境，播放失败都不能让舞台空白。

#### 4.1 切换与恢复规则

- 切任务：取消旧加载、旧播放回调与旧跟踪渲染；清空结果、节点选择、比较滑杆值；载入新任务，并停在其有效起点。明确用户点击后可直接播放，但必须等待媒体与脚本就绪。
- 切原始／分析／对照：保留同一播放时间，不刷新资源、不重播。默认进入分析；对照初始 50%。
- 切行业预设：回到预设起点，清空上次事件，重新对应处理链。前一次规则结果不能残留。
- 暂停：视频、框、轨迹、扫描与链节点状态全部暂停。菜单的 hover/focus 反馈可继续。
- 重播：回到片段开始，清除已触发事件；同一次正向经过事件时只触发一次。
- 快进／倒退：直接按当前时间推导状态；不追补所有跳过的动画。不因拖动导致多个结果卡堆叠。
- 页面切到后台或舞台明显离屏：暂停解码与动画。只有此前由系统临时暂停、未被用户手动暂停且媒体仍可见时才允许恢复。手机默认需要点击恢复。
- 改变窗口大小／屏幕方向：保持视频时间和用户选择，重新计算视频内容矩形，再绘制图层。

首版每次只解码当前一个业务视频。Hero 若日后加入视频，业务舞台播放时暂停已离屏的 Hero。

### 5. 精准叠加与比较

#### 5.1 坐标与线条

所有标注坐标来自实际媒体的归一化坐标，不记录桌面截图像素。响应式缩放后，框和区域随同一内容矩形映射。SVG 的 `viewBox` 可采用实际源宽高，或统一归一化映射；关键是只用一种规范，不能重复缩放。

线宽保持约 1.5–2 CSS px，采用非缩放描边或等效换算。目标框贴合可见目标但不强求识别级精度；按实际标注误差验收。普通文字不能随源画面从 1280 px 缩到 320 px 后一起变成 4 px。

区域是地面上的同一块区域，因此镜头移动时，四角在屏幕上的位置会改变。必须使用经过校准的逐时间投影；不能让固定屏幕矩形代表固定地面区域，也不能让区域追着车走。

遮挡、对象消失、身份无法确认时，隐藏或中断跟踪，禁止跨间断插值。出画后不沿边缘保留幽灵框。轨迹仅显示已观察的短尾段，不画预测道路路线冒充目标轨迹。

#### 5.2 命中、拖动与层级

视频基础层 `z=0`；区域与目标层 `z=10`；选中目标提示 `z=20`；播放控制与比较把手 `z=30`；必要菜单 `z=40`。导航只在自己的页面层级中浮动，避免盖住全屏退出按钮。

装饰标记默认 `pointer-events:none`，只有可点选目标和显式控件接收事件。目标很小时使用画面外的“目标 1”按钮提供等价操作，不画一个覆盖半条道路的虚大框增加点击面积。

比较把手支持 pointer capture，`pointercancel`、窗口失焦都能释放；拖动范围限制在实际视频内容区。开始拖动（或键盘调整对照值）时暂停视频，操作结束后保持暂停，由用户点击播放恢复。不要因为对照滑杆阻止整个页面纵向滚动。

### 6. 无障碍与输入方式

- 所有核心动作可通过键盘完成；控件有可见焦点，图标按钮有明确名称。
- 任务标签按 tabs 模式实现；方向键移动焦点，Enter／Space 激活，避免仅焦点移动就触发视频下载。参考 [WAI Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)。
- 触摸目标至少 44×44 CSS px，这是本项目设计要求；不把桌面 hover 作为唯一解释方式。
- 不以颜色作为事件成立的唯一提示，同时提供文字和图标。
- 结果变化可用简短 polite live region 提示一次；不要每一帧播报目标位置。
- 响应系统“减少动态效果”：关闭自动播放、扫描、视差和位移动画，保留手动播放与直接状态切换。[MDN 说明](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)
- 200% 页面缩放仍能操作，不用固定高度裁掉文字。深色系统不自动把品牌页面转换为黑色；先保证既定浅色主题。

### 7. 性能与加载预算

这些是实现目标，不是本轮测得的成绩：手机条件下核心内容优先出现；争取 LCP ≤2.5 s、CLS ≤0.1、INP ≤200 ms，报告测试设备与网络条件，不能只填写分数。

- 首屏只请求必要字体／图像／脚本；视频按进入视口和明确交互加载。
- 原始三视频合计约 48 MB，不能在首页加载时全部预取；自然语言原片约 32 MB，更要制作适合网页的派生版本。
- 派生 MP4 采用浏览器兼容编码、网页用静音音轨策略与 faststart；保持比例、时间映射和可见内容。保留原件及其哈希。画质与码率通过实际目标可辨识度选择，不用统一极低码率。
- 初始静态页面脚本争取压缩后 <200 KB；无需为演示引入图表库、3D 场景引擎或完整后台组件库。
- 主舞台逐帧更新应局部化；不每帧重建整棵 DOM 或触发整个应用状态更新。
- 离屏停止回调，释放废弃监听器；加载错误和自动播放拒绝都有可见回退。
- 固定图片尺寸／比例以避免布局跳动。对照和目标放大使用同一媒体源，不并行下载两份视频。

### 8. 必须截图／录屏验证的尺寸

布局至少检查：320×740、390×844、430×932、768×1024、1024×768、1366×768、1440×900、1920×1080、2560×1440。另检查手机横屏 844×390 与浏览器缩放 200%。

核心状态至少保存：行业默认、区域事件发生、原始／分析对照、自然语言结果、以图搜图结果、手机展开完整链、手机菜单、预约字段错误、媒体失败、减少动态模式。浏览器自动化手机视口不能替代真实 iOS 自动播放／解码验证；尚未测过真实设备必须写在交付限制里。

### 1. 架构决定

|---|---|

分析数据必须绑定 `mediaId + sha256 + encodedWidth + encodedHeight + duration + timebase`。更换、剪辑、变速、裁切或扩图后，旧轨迹不能直接复用。压缩副本若维持相同画面视野和时间轴，可沿用归一化坐标，但要保存副本自己的哈希、尺寸和与原片的绑定，并复核起始偏移、末尾时刻及多个中间时间点。

每个预设分析对象可配置 `playbackWindow: { startSec, endSec }`，在**未剪原片的源时间轴**上限定可播放区间 `[startSec,endSec)`，省略时为 `[0,media.durationSec)`。短段须实际校准，不能把候选区间当已完成标注。播放、重播、切场景和切行业预设都使用所选窗口的 `startSec`；时间轴拖动限制在窗口内。UI 可显示相对窗口起点的经过时间，但坐标样本、事件和证据继续保留源片秒数，不减去起点后混存。

`PresetPresentation` 承载预设 selection、mediaId、查询文字/参考图以及可选 playbackWindow。页面不把示例查询和参考图 URL 硬编码在点击事件里。窗口解析顺序为预设 presentation、analysis、全片默认值；前两者都提供时必须一致，否则拒绝启用分析叠层。参考图包含真实 url、来源 mediaId、timeSec 和可选源画幅 crop；尚未制作的参考图保持未配置，不能捏造一个貌似存在的 URL 或提前启用匹配。

窗口只是播放限制，不剪文件。若后续真的剪出派生视频、变速或拼接，应建立新 mediaId、哈希及重新绑定的分析数据，或另行扩展明确的源片/派生片时间映射协议。不能把这种派生片放入 `renditions.timeline = identical-presentation-timeline`；当前 v1 renditions 仅允许视野及呈现时间轴均一致的传输副本。

`timebase: presentation-seconds` 指浏览器媒体呈现时间，单位秒；不是“每帧 1/24 秒”替代文件真实 PTS。`encodedTimeBase` 若写入，必须来自 ffprobe，而不是由帧率猜测。当前示例没有猜测编码 time_base。

`posterUrl` 对应真实抽帧。加载前不能把 0 秒的叠层放在其他时刻的海报上。尚无已验证时间绑定时，海报只呈现静态画面，开始播放后再开启叠层。

### 5. 视频时钟与交互状态

#### 5.1 唯一时钟

**视频解码呈现时间是目标框、地面区域、轨迹、阶段动画和事件显示的唯一时钟。** 不能用点击时记录的 `Date.now()`、独立 GSAP 时间线或固定 `setInterval` 驱动识别结果；缓冲和用户暂停会让它们漂移。

优先使用 `requestVideoFrameCallback` 的 `metadata.mediaTime`；不支持时，在播放中的 `requestAnimationFrame` 回调读取 `video.currentTime`。`timeupdate` 只用于粗粒度 UI 更新，不承担逐帧跟踪。回调并非严格实时保证，渲染逻辑必须轻量且允许掉帧。[MDN：requestVideoFrameCallback](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)

每次媒体帧更新依次进行：

1. 根据媒体时间取样目标和地面区域，遇到 gap 不跨越插值。
2. 经唯一坐标映射转换到当前视频内容矩形。
3. 只更新必要的 SVG 属性和 HTML transform；保留 DOM 节点，不每帧重建整棵树。
4. 由当前时间重新推导可见事件、演示阶段和结果状态；时间跳回时旧结果也消失。
5. 只有语义状态发生改变才更新节点文字或状态面板，避免每帧刷新全局 UI。

原生 JS 使用小型 store 加订阅即可。如果独立项目使用 React，几何绘制仍由独立 Renderer 和 ref 执行，不每帧 `setState`。滚动动画、鼠标微位移可以有独立动画时钟，但绝不能承担目标追踪。

#### 5.2 状态转移规范

| 触发 | 必须执行的行为 |
|---|---|
| 初次进入舞台 | 显示海报与预设；媒体和分析数据就绪后允许播放；自动播放失败转为显式播放按钮 |
| 切换行业/自然语言/以图搜图 | 中止旧请求，停止旧 frame callback，暂停视频；清空目标/结果；只提交最后一次选择对应资源；新视频定位到所选预设 playbackWindow.startSec（未配置则 0） |
| 同行业切“车辆检测／区域进入” | 暂停同一 video，取消旧 seek 意图，清空目标/轨迹/事件；替换 chain、ROI、事件层，定位到新预设 playbackWindow.startSec（未配置则 0）；新帧就绪后等待用户播放 |
| 暂停 | 冻结已渲染的目标与阶段；暂停扫描/脉冲等随演示运行的效果；按钮准确显示“播放” |
| 缓冲/waiting | 停止推进所有语义状态；不假装算法仍在分析；保留稳定的当前帧 |
| 拖时间轴 | 设置窗口范围内的源片时间 seek；清除陈旧 overlay；等待 seeked/新媒体帧再绘制该时间点；快速拖动只保留最后一次目标时间 |
| 播放结束 | 到达 playbackWindow.endSec 或文件 ended 均结束当前演示，提供重播；用户主动交互后不突然自动重播。若空闲循环，显式重置到窗口起点后再播放 |
| 点击重播 | 定位到当前预设 playbackWindow.startSec（未配置则 0），清除事件/选择/轨迹；保留当前场景、行业预设和观看模式 |
| 舞台离开视口 | 暂停并记录“离屏暂停”；返回后只恢复离屏前本来在播放的状态 |
| 用户手动暂停后滚出再滚回 | 仍保持暂停，不能被自动恢复覆盖 |
| 页面后台/恢复 | `visibilitychange` 暂停；恢复遵守播放意图，不突然发声或重播 |
| 视口尺寸/横竖屏变化 | 仅重算坐标映射；不改变媒体时间，不换一套猜测坐标 |
| 销毁舞台或页面离开 | 取消 frame/rAF 回调、observer、流订阅、事件监听和未完成请求 |

媒体总时长 10 秒不代表存在 PTS 恰好为 10 秒的视频帧。窗口末尾同理：结束后若停留在最后画面，叠层应冻结在窗口内最后已呈现帧的 mediaTime，不能直接拿 duration=10 或排他的 endSec 重新采样导致最后目标和结果消失。实现者需监听实际媒体时间判断窗口结束，不等原片 ended 才停止；回调降级路径也要保留最后有效渲染时刻。重播统一回窗口起点。

用独立的 `userWantsPlayback` 与 `pauseReasons` 表达播放意图，避免一个 boolean 同时表示“用户暂停”“离屏”“缓冲”。处理 `video.play()` 返回 Promise 的拒绝；`muted`、`playsinline` 有助于内联静音播放，但不保证任何浏览器都会自动播放。[MDN：play()](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play)、[自动播放策略](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)

### 6. 视频与 SVG 坐标系统

#### 6.1 数据坐标

`Point01(x,y)`、`Box01(x,y,width,height)` 全部相对**未裁切的编码画幅**归一化，左上为 `(0,0)`，右下为 `(1,1)`。禁止记录桌面截图 CSS 像素，再按手机宽度简单除比例。部分离开画面的框需要裁到实际画幅，完全离开的目标隐藏。

播放器仅包含一段视频。外层 `stage` 为相对定位和裁切容器；视频使用实际源比例或 `object-fit: contain`。SVG 覆盖视频真正的内容矩形，HTML 标签使用相同映射；外侧操作面板不参与坐标。

设编码画幅为 `W × H`，视频元素可用内容框为 `Cw × Ch`，并且无额外 padding/border、`object-position: 50% 50%`：

```text
contain: s = min(Cw/W, Ch/H)
cover:   s = max(Cw/W, Ch/H)   （仅解释映射，主舞台默认不使用 cover）
Rw = W*s; Rh = H*s
ox = (Cw-Rw)/2; oy = (Ch-Rh)/2
屏幕点 = (ox + x*Rw, oy + y*Rh)
屏幕框 = (ox+x*Rw, oy+y*Rh, width*Rw, height*Rh)
```

若 CSS 使用其他 object-position，应把百分比位置传入同一个 Mapper，而不是 SVG 自己猜测。SVG 可以直接使用 `viewBox="0 0 W H"`，放置在 `(ox,oy,Rw,Rh)`；归一化坐标乘 W/H 写入 viewBox 坐标。裁切、标签避让和命中测试同用这套转换。`cover` 会裁掉画面，`contain` 会产生留边，因此视频元素边界不总等于实际图像边界。[MDN：object-fit](https://developer.mozilla.org/en-US/docs/Web/CSS/object-fit)

使用 ResizeObserver 监听舞台内容尺寸，下一帧合并更新；不要每个目标每帧调用布局读取。绘制与测量分开以避免强制同步布局。

#### 6.2 摄像机在动时，区域也要动

三个视频不是固定监控镜头，第三支尤其有推进。目标框需要逐时间点跟踪；蓝色地面区域也必须跟随道路的透视与镜头变化。网页上固定一个四边形，车动时把它当真实地面区域，会立即露馅。

第一版使用复核过的**投影多边形序列**：每个时间样本记录同一块地面的有序顶点；密度按镜头运动和误差确定。相邻样本可线性插值的前提是相同顶点数、顺序和同一连续片段，并经中间帧检查。较复杂的项目可离线做平面跟踪/单应性，再烘焙到逐帧投影；运行时契约不依赖某个跟踪软件。

车辆进入判断使用已标注接地点，或约定框底边中心。不能用车顶框中心随意代表车辆落地点。进入事件要有真实可见的“区域外→区域内”上下文；目标被遮挡后在区域内重新出现，不能凭空补一个进入事件。

`RegionEntryRule.minimumInsideSec` 表示越界后必须连续可观察的区域内停留时长；`AnalysisEvent.timeSec` 是满足该时长后**事件成立的确认时刻**，不是最初越过边界的时刻。首次可见越界可另记 `observedCrossingTimeSec` 并关联对应证据。`visible.startSec >= timeSec`，不能为了视觉节奏提前显示事件。途中遮挡导致连续性无法确认时，不能凭隐藏时段累计成立时间。

若视频某处 AI 生成形变严重、车体消失或背景不连续，缩短该目标可见时间或选择另一段清楚目标，不跨缺口画一条光滑轨迹。静态页面能力必须建立在可复核的样片上。

#### 6.3 轨迹采样与标注生产要求

- 本包没有最终跟踪数据。实施者需针对三段现有 MP4 抽取时间样本、标注、回放并人工校正，然后生成 JSON。
- `TrackSegment` 是连续可观察片段；只有能够确认仍是同一对象的遮挡或离画，才保留 track.id 并另起 segment。身份不确定时必须新建 `ObjectTrack.id`，不能继承身份或关联旧对象的进入事件。gap 不插值、不画连接线。
- 当前时刻超出 segment 或相邻样本间距超过 `maxInterpolationGapSec`，隐藏该段结果；不要沿速度无限外推。
- 轨迹只显示当前媒体时间以前的短尾，并且只使用同一连续 segment；不能提前显示未来路径。
- 每个 scene 至少验证开始、中段、结束及所有遮挡/事件边界；不要只在首帧对齐就宣称跟踪完成。
- 本轮 `authored-demo` 的 `reviewedAt` 必填，只在完成实际回放复核后填写。未来 `algorithm-output` 必须提供 runId、modelVersion、conditionsId，人工复核时间可选，不以人工回放作为真实算法结果展示的前置条件。`ready` 仅表示数据满足渲染契约，不表示人工确认准确。`annotation-required` 不能用空数组假装“未检测到目标”，应显示清楚的演示待配置状态。

### 7. 三种观看模式与算法链

#### 7.1 原始 / 分析 / 对比

- 原始：播放同一视频，隐藏分析叠层；保留必要播放器控制。
- 分析：显示该预设的目标、区域和轨迹；结果卡与算法链同步。
- 对比：**仍然只有一个 video**；用 clip-path 或遮罩限制分析叠层显示在滑块一侧，另一侧保持原始画面。禁止双播放器并排后各自播放造成漂移。
- 对比滑块使用原生 range 或等价可访问控制；鼠标、触屏、方向键可用。开始拖动或键盘调整时暂停视频，结束保持暂停，由用户主动恢复；百分比位置只作用于叠层可见范围，不改变视频内容坐标。
- 算法链说明与结果面板不被视频对比遮罩裁掉；交互目标只在实际可见的一侧接收点击。

SVG 几何层 `aria-hidden`，对应可操作目标提供 HTML 按钮和文字结果。全屏透明 SVG 不应吞掉播放、拖拽、页面滚动等事件；普通几何 `pointer-events: none`，仅目标命中层显式开启。

#### 7.2 行业两预设

预设按钮固定为“车辆检测／区域进入”。“车辆检测”展示“视频输入→抽帧处理→车辆检测→结果输出”；“区域进入”展示“视频输入→抽帧处理→车辆检测→目标跟踪→条件判断→事件输出”。切换时暂停视频、清空原有事件，回到新预设已校准的 playbackWindow.startSec；复用节点平滑重排，新增节点短暂强调，非必要节点退场。

自然语言链固定为“画面输入→目标分析→文本条件匹配→结果输出”；以图搜图链固定为“视频输入→抽帧处理→车辆检测→外观特征→相似匹配→结果输出”。四条链都在 `contracts/examples.ts` 给出概念结构，节点说明与实际后端执行记录保持区分。

这表达算法链的“可配置、节点可复用”。节点流动线、点亮和阶段节奏是讲解动画，不应标为实测执行顺序、实际耗时或逐帧推理。不要把每个节点做成漫长的点击闸门，用户可以一眼看懂完整链。

如果用户在 8 秒切到“区域进入”，播放器应回到该预设窗口起点，不继承 8 秒时的结果；再次播放时，事件严格按源片时间出现。窗口应包含演示所需的进入前后上下文。预设切换过渡与数据真实性不能冲突。

#### 9.2 流式结果与版本

初版契约使用完整快照更新：`schemaVersion + runId + sequence + document`。前端只接受当前请求、当前媒体、当前 run 的新序列。重连去重依据 runId/sequence，不按接收时间猜顺序。若服务以后提供增量 track，需另行定义 delta 与删除、重置、补帧语义，不把它偷偷塞进同一个 v1 schema。

SSE 是可选传输，不预先绑定它。原生 EventSource 对自定义鉴权头有限制；若后端依赖 bearer header，应由适配器选择 fetch stream/其他机制，不能把 token 放在 URL。关闭页面、换场景时取消订阅。[MDN：SSE](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)

#### 9.3 latest request wins 与错误

每次切场景创建新的 requestId 和 AbortController，先取消旧请求，再提交新状态。即使取消没生效，响应到达时仍检查当前 requestId；旧响应不能覆盖新 tab。流式更新同样检查 runId、mediaId 和版本。[MDN：AbortController](https://developer.mozilla.org/en-US/docs/Web/API/AbortController)

只对可安全重试的读取做有限次数退避；提供手动重试。429 遵循 Retry-After，401/403、schema 错误和资源缺失不能无限重试。预约 POST 不自动重复提交，后端接入时约定幂等键与回执。区分：媒体加载失败、分析暂不可用、浏览器播放被阻止、无匹配目标；它们不是同一种“出错”。

#### 9.4 运行时校验

实现者必须写边界校验；仅写 TypeScript interface 不足以保护运行时：

- schemaVersion 受支持；scenarioId/presetId 组合合法；hash 与实际绑定媒体一致。
- 静态预设必须有合法 presetId；未来任意分析任务必须有当前 runId。两者的模式来源由 Provider 明确区分，不能用缺省值补出某个演示结果。
- 所有数字有限且在合法范围，时间按升序、位于媒体时间轴；区间 `start < end`，端点语义 `[start,end)`。
- playbackWindow 位于源片 `[0,durationSec]` 内，省略时全片；seek、重播和切预设均遵守窗口，事件判断所需的前后上下文必须实际可见。派生剪辑不能冒充相同时间轴传输副本。
- presentation 与 analysis 的媒体/窗口绑定一致；查询文字由预设对象提供；参考图必须真实存在且来源时间/crop 可复核，缺失时显示未配置而不是请求假 URL。
- box 和 polygon 在规范化画幅范围；每个 polygon 至少三点，连续插值片段顶点数/顺序一致。
- samples 覆盖有效 interval；不跨 gap 插值；轨迹 id、ROI id、event evidence 引用全部存在。
- 身份不确定不得复用 ObjectTrack.id；区域进入确认时间满足连续可观察停留条件，visible.startSec 不得早于 timeSec，越界时刻与事件成立时刻分开记录。
- ready 必须包含 provenance；authored-demo 必须有实际 reviewedAt 且不可写实测 confidence；algorithm-output 必须有 runId/modelVersion/conditionsId，reviewedAt 可选。示例故意不提供虚构坐标。
- URL 只接受本地站内或显式配置的可信 HTTPS 媒体源；文本用 textContent 安全渲染，不执行后端 HTML。
- 外部资源数目、JSON 大小、轨迹点数设合理上限，避免异常数据卡死渲染。

### 11. 媒体服务与性能

现有 `website/serve.mjs` 的 MIME 表没有 `.mp4`，并且没有 Range 响应，当前会把未知扩展当 `application/octet-stream` 且整文件读入内存。新视频预览实现要补 `video/mp4`、正确 Content-Length/HEAD，并处理单范围请求的 206/Content-Range 与越界 416，或使用已经正确支持媒体 Range 的本地静态服务；不要把“localhost 能显示首帧”当完整 seek 验收。[MDN：HTTP Range](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Range_requests)

正式部署需验证静态托管/CDN 实际响应。跨域只播放视频与 Canvas 取像素的条件不同：目标放大或证据截图如果通过 Canvas，媒体源必须允许相应 CORS，并在设置 src 前正确配置 crossOrigin；失败时使用预导出同源证据图或禁用取帧。不能试图绕过浏览器画布安全限制。

建议首轮性能预算（待实际测量验收，不是已达到的数据）：

- 手机首屏先加载必要 HTML/CSS/JS 与小海报，不自动下载三支视频；32 MB 的自然语言原片必须另做网页传输副本后再正式上线。
- 三段原片保持字节不变归档；浏览器副本可压缩、移除不需要的音轨并优化元数据位置，但保持时间轴、视野和方向。每个副本有自己的 manifest 与校验。
- 桌面也只让当前 tab 播放；其他视频采用 `preload=none` 或由选择动作加载。不要假定 `<video loading=lazy>` 足够替代明确的加载策略。
- 数据文件和 SVG 先满足少量可理解目标；首版每段聚焦 1 个主要对象和必要辅助目标，不追求满屏框。
- Renderer 每帧只做采样和属性写入；任务分析、跟踪计算、模型推理不在首页主线程执行。
- 高成本阴影、模糊、滤镜不覆盖整段视频；手机关闭倾斜和大面积发光，用边缘高亮与短脉冲保持视觉一致。
- 不强制引入 Three.js/WebGL。若后续 Hero 加轻量粒子，独立懒加载，失败不影响核心视频和预约。

视频只负责实景运动。识别框、区域、轨迹由网页 SVG / Canvas 叠加；搜索框、参考图、算法节点、事件结果由网页 DOM 展示。后期工作的重点是提取和校正跟踪数据，不把文字、按钮或识别图形永久压进现有视频。

视觉层级由下至上：

1. 原始视频：保持亮度和真实环境，不整体覆盖蓝色滤镜。
2. 空间图层：贴地的区域边界、少量路径线；每个顶点跟随场景透视变化。
3. 目标图层：精确包围被关注的对象，主体仍看得清。
4. 信息图层：一句短标签或事件提示；避开被跟踪目标。
5. 舞台外操作：播放、原始 / 分析、预设切换、算法链、详情。手机上全部放在画面外。

推荐表现参数作为初始设计值，开发者根据实机效果微调：

| 元素 | 表现 | 禁止出现的问题 |
| --- | --- | --- |
| 主目标框 | 品牌蓝四角框，常态约 2 CSS px；选中时一次 180–260ms 收拢反馈 | 每帧缩放闪烁、框比目标大数倍、框挡住车身 |
| 区域 | 约 8%–12% 蓝色填充，约 1.5–2 CSS px 边界；进入时一次短暂增亮 | 发光盖住道路、区域跟着屏幕而不跟着地面 |
| 轨迹 | 只保留短尾迹；颜色和透明度从近到远衰减 | 将旧的屏幕坐标连成地面轨迹，产生飘浮或穿越物体 |
| 事件 | 紧凑提示“进入指定区域”，可点击打开暂停态详情 | 自动弹大面板、长段说明遮住主体、冒充真实报警 |
| 算法链 | 处理步骤之间有一次清晰的数据流动；播放中只突出当前有关步骤 | 六个节点不停闪动、循环扫描线、装饰性乱码 |
| 对比 | 切换“原始 / 分析”时视频不重置，叠加层约 160–220ms 淡入淡出 | 为显示科技感替换实景颜色、整块视频翻转旋转 |

科技感来自“目标被选中 → 条件生效 → 节点工作 → 结果出现”的因果关系。无需添加满屏粒子、雷达、虚构坐标、虚构识别率或不断滚动的代码。

### 3. 三支演示共享的操作规则

- 三个主标签固定顺序：**行业场景 → 自然语言 → 以图搜图**。同一时刻只播放当前标签的视频。
- 当前视频、叠加层、算法节点、事件状态共用一个媒体时间源。暂停、拖动进度、缓冲、标签切换后必须重新计算所有状态，不能让独立计时器继续走。
- 算法链是可配置工作流的演示，节点点亮不代表实际处理耗时，也不显示模拟“耗时 12ms”。
- 视频控制至少包含播放 / 暂停、重播、原始 / 分析；支持键盘。播放完停在可读的结果帧，不倒放，不依赖无缝循环。
- 进入页面时默认行业场景和“区域进入”。桌面在可视范围内可尝试静音播放一次；播放被浏览器阻止时显示明确的播放按钮。自然语言和以图搜图由用户切换后启动。
- 切换行业预设时，暂停并回到该预设的 `playbackWindow.startSec`（未配置则 0），清空旧事件，新帧就绪后等待用户播放；切换原始 / 分析时不重播。
- 舞台提供 `原始 / 分析 / 对照` 三种观看方式。“对照”使用同一支视频，在其上用裁切蒙版显示部分分析图层，拖动分界线比较；不叠两个播放器，不让左右画面独立走时。开始拖动或键盘调整时暂停，结束保持暂停，用户主动恢复。手机使用同样的分界控件或一键切换，不能只依赖鼠标。
- 点击事件 / 匹配结果时暂停视频，聚焦当前目标详情；关闭详情后保持暂停，由用户决定继续。不能在用户读文字时继续带走目标。
- 用户设置减少动态效果时默认封面或已校准的静态结果帧，仍可主动播放；禁用扫光、入场弹跳和重复装饰动画。缺少跟踪数据时不能把封面画成未经验证的结果。
- 以下时序均是 10 秒媒体的编排建议。需要目标进入、遮挡开始、目标出画的地方，以标定后的真实时刻替代建议区间；不能为了凑表格而制造结果。

### 4. 行业场景：让外行看懂“识别车辆”与“理解事件”的区别

#### 4.1 素材观察与目标选择

蓝白厢式车位于画面右側道路，0.20 秒和 2.50 秒较清楚；5 秒之后明显变远，7.50–9.70 秒不宜继续用夸张大框强调。建筑与道路相对画框移动，说明摄影机不是固定机位。

优先关注这辆蓝白厢式车，不用后来进入画面的红车替它接续同一个 ID。区域应选在其实际行驶车道的前方，保证片头车在区外、之后能够穿入；具体区域四角和进入时刻必须在标定后决定。这里不把道路描述成园区入口，也不改变原素材的行车方向。

#### 4.2 两个可切换预设

| 预设 | 算法链可见节点 | 视频呈现 | 结果 |
| --- | --- | --- | --- |
| 车辆检测 | 视频输入 → 抽帧处理 → 车辆检测 → 结果输出 | 只显示当前可见车辆框；无区域，无进入事件 | “车辆目标” |
| 区域进入（默认） | 视频输入 → 抽帧处理 → 车辆检测 → 目标跟踪 → 条件判断 → 事件输出 | 保留检测，增加区域、跟踪与进入反馈 | “进入指定区域” |

节点增加、消失时通过 220–320ms 平滑排列变化表达配置变化。两个预设共用同一段视频和已验证目标标定，但输出类型不同。无需开发完整节点编辑器，也不让访问者随意连接尚未支持的节点。

#### 4.3 10 秒时序：区域进入预设

| 媒体时间 | 视频上的效果 | 舞台外界面与算法链 | 实现前提 |
| --- | --- | --- | --- |
| 0.00–0.60s | 原图呈现，区域边界轻量建立 | 显示“区域进入”；视频输入、抽帧处理建立连接 | 区域此刻确实位于前方，目标尚未进入 |
| 0.60–1.60s | 蓝白厢式车获得短标签“车辆 A”和贴合目标框 | 车辆检测突出，目标跟踪接入 | 标签 ID 仅为演示编号，不代表车牌 |
| 1.60–进入前 | 框继续跟随；区域保持低透明度 | 条件状态显示“区域外”，突出目标跟踪与条件判断 | 每帧目标位置与区域都已校准 |
| 建议 2.50–4.00s 内的实际进入时刻 | 目标越过区域边界；区域边缘增亮一次 | “区域外”变成“区域内”；事件输出点亮 | 时间由接地点越界测定，不硬编码成 3.00s |
| 进入后约 0.30–1.50s | 保持目标框；短提示“进入指定区域”出现 | 事件结果可点；展示小型结果出口或“查看结果” | 同一次进入只创建一个事件 |
| 约 5.00–8.50s | 车辆逐渐远去；看不清后结束其框和短尾迹 | 已发生的事件仍保留；节点转为安静状态 | 不把大框强行贴到远处任一车上 |
| 8.50–10.00s | 原画面继续，或在已验证结束帧停留 | 显示“重播”“切换为车辆检测” | 显示结果发生时刻的留存信息，不假称仍在实时跟踪 |

如果无法在该车仍清楚时得到真实的区外 → 区内过程，先调整区域位置再复核。若仍无法成立，第一版仅演示车辆检测并把区域进入作为待完善功能；不得将移动区域主动扫过车辆造成“进入”假象。

车辆检测预设沿用 0.00–1.60s 建立过程，此后只显示已核准的可见目标框与“车辆目标”，没有区域、进入条件、事件卡。两者的差异必须可见，不能只换标题。

#### 4.4 区域与轨迹的物理关系

- ROI 是地面上的固定多边形，摄影机移动时，它在像素坐标里会变化。可离线跟踪路面平面并求每帧变换，或对这段短片逐帧 / 关键帧校正顶点。
- 进入判据使用约定的车辆地面接触点，例如投影到地面的车辆底部中心近似点；不能用整个检测框“碰到区域”代替，除非产品真实规则就是如此。
- 只在有效可见且规则条件完整时计算演示事件。边界附近加短暂稳定确认或滞回，避免抖动重复出事件；参数属于演示配置，不能写成产品固定能力。统一将 `AnalysisEvent.timeSec` 定义为稳定确认完成、事件成立的时刻；实际越界帧通过证据引用保存，结果不得在确认完成前出现。
- 车辆历史位置不能直接把历史屏幕坐标连成贴地轨迹。需要把历史地面点重投影到当前帧，或只做短的目标运动提示并明确不表达物理路径。第一版允许不画长轨迹，优先保证框和区域正确。

### 5. 自然语言：描述关注目标，然后看到匹配对象

#### 5.1 素材观察与安全演示范围

0.20 秒的骑行者较完整；到 1 秒已被枝叶部分遮挡。2.50 秒可见不止一个人物，4–5 秒树枝遮挡显著，6 秒中下部有较近骑行者但仍有花枝遮挡，7.50 和 9.70 秒的中下部骑行者更完整。不能根据衣服相近就认定全程只有同一人，也不能把一次遮挡前后的任意两个骑行者用同一个轨迹连起来。

本片只说明“查找骑行人员”。不同时承诺人数统计、未戴头盔、危险骑行、步行者排除等没有验证的能力。优先制作 **6 秒以后中下部较近骑行者的可见片段**；早期骑行者作为单独可见轨迹段，保留不同内部 ID。

#### 5.2 10 秒时序

| 媒体时间 | 视频上的效果 | 搜索与算法链 | 实施约束 |
| --- | --- | --- | --- |
| 播放前 / 0.00–0.40s | 保持首段画面清晰，不做全屏扫描 | 搜索栏预置“查找骑行人员”；用户点击或标签默认演示触发；突出语言解析 | 文本是预设，不假装任意自然语言都已接入 |
| 0.40–可见段结束 | 可见骑行者获得精简目标框 | “骑行人员”条件 chip 与对应检测 / 匹配节点亮起 | 仅在已校准且仍可见的区间画框 |
| 约 1.00–5.60s | 枝叶遮挡时隐藏框或仅在极短可确认部分遮挡阶段使用虚线；不穿树继续跑框 | 条件 chip 保留；可显示“关注骑行人员”，不显示虚构新增结果 | 不把所有花枝中的人形噪点都标出来；可提供“查看匹配片段”直接跳到已验证结果时刻 |
| 约 5.60–6.80s | 近处骑行者重新进入可见区，建立新的可见轨迹段 | 匹配结果出现；显示“骑行人员”而非“重新识别到同一人” | 具体开始时刻由逐帧可见性确认，不固定认定 6.00s 完全无遮挡 |
| 6.80–9.50s | 精确跟随目标；标签避开树冠，最多保留一个主目标 | 画面输入 → 目标分析 → 文本条件匹配 → 结果输出；可点击结果查看当前局部 | 7.50 / 9.70s 较完整，适合呈现清晰结果 |
| 9.50–10.00s | 保留最后有效结果帧 | “重播演示”及“查看匹配片段” | 不跨越不可见段拼成无中断轨迹 |

本片中间遮挡时间较长，因此第一版交互应有一个无需等待全片的“查看匹配片段”：跳到已校准的约 6.5–7 秒区间并播放到结尾。此入口只改变播放位置，所有叠加状态仍从媒体时间重新计算。

如首页节奏仍慢，可另存约 6.5–10 秒的短派生片，用于默认展示，完整 10 秒原片留作“查看完整演示”。这是建议的后续剪辑方案，本次没有执行剪辑；一旦剪辑必须重新记录媒体版本与时间映射。

#### 5.3 推荐片段与时间映射

先不剪原件，可以在播放器中使用片段起止点；未来需要降低下载量时再生成单独的短派生文件。三支的候选窗口如下，最终边界仍需逐帧校准：

| 场景 | 候选源片时间 | 推荐用途 | 是否已完成逐帧验收 |
| --- | --- | --- | --- |
| 行业场景 | 0.00–约 5.50s | 检测、跟踪、进入事件的主过程 | 否；进入时刻与有效区域待标定 |
| 自然语言 | 约 6.50–9.75s | 更快看到清楚骑行者的结果预览 | 否；确认可见性及连续身份后定边界 |
| 以图搜图 | 约 6.00–9.75s | 白轿车的主要相似目标展示 | 否；先确认车辆外观连续，再定主轨迹 |

首版不物理剪辑，使用统一契约的 `playbackWindow.startSec/endSec` 配置源片有效区间；文中 `sourceIn/sourceOut` 是剪辑概念名，分别对应这两个值。直接令 `video.currentTime = playbackWindow.startSec`，渲染仍使用源片媒体时间。若未来物理剪辑，`sourceTime = sourceIn + clipTime` 仅适用于未变速、未拼接的单段；这需要另建派生媒体及显式时间映射，不能填入“相同完整时间轴”的压缩副本字段。不同播放速度仍以真实媒体时间为准，不按墙钟推算。

物理剪辑的离线加工记录必须保存源媒体 ID、源哈希、源入点／出点与派生哈希，但这些记录不能未经协议扩展直接作为现有 v1 字段注入。首版片段重播回到 `playbackWindow.startSec`，结束停在该区间最后有效结果帧。短段、全片共用一个播放器组件，切换后清理前一次取样状态。一个 3.25 秒的短段不能把原来的 10 秒流程压缩播放，而要把预设搜索放在播放前，把节点和结果改为该短段的真实阶段。

#### 5.4 输入行为

静态版可以让输入框聚焦和编辑，但运行入口只执行明确提供的预设；自由文本提交时提示“当前展示预设演示”，并提供“使用示例：查找骑行人员”。不应收到任意文字后仍悄悄播放同一个结果，也不要制造假的聊天回答。

网页上只显示一行输入、一枚条件 chip 和简短结果。不要把语言解析写成大段对话。桌面可用轻量扫光把输入的条件传递到算法链，手机用节点状态变化代替扫光。

### 6. 以图搜图：参考外观与实景目标建立对应

#### 6.1 素材观察与目标选择

本片摄影机沿道路前推，近处目标迅速放大和出画。2.50–3.50 秒存在若干可见白车；5 秒画面右下是体积较大的白色 SUV；6、7.50、8.50、9.70 秒右侧近处可见一辆白色轿车。**不能将 5 秒的 SUV 和之后的轿车认作同一辆车；抽帧也不足以证明 6–9.70 秒之间不存在生成形变或 ID 切换。**

优先选约 6–9.70 秒的白色轿车作为主匹配展示段，逐帧确认后再定段。参考小图应从所选目标的清晰帧裁切，注明“示例参考图”；当前使用同片生成的示例参考，不宣称已演示跨摄像头或跨视频找回。

实际参考图由实现者另存派生文件，保留原视频不变。本次未交付目标裁切图，也未给出未经验证的框坐标。

#### 6.2 10 秒时序

| 媒体时间 | 视频上的效果 | 参考图 / 算法链 / 结果 | 实施约束 |
| --- | --- | --- | --- |
| 播放前 / 0.00–1.00s | 先看见完整道路与车流 | 舞台外显示“示例参考图”；点击“查找相似目标”启动预设 | 参考图使用后段清晰轿车，不用 5 秒 SUV 替代 |
| 1.00–2.50s | 原视频继续，无需大面积遮罩 | 参考图条件进入外观匹配步骤；连线只在舞台外短暂出现 | 不以等待动画模拟真实计算耗时 |
| 2.50–5.60s | 若前段白车有经过标定且适合表达的相似结果，允许显示短段候选框；否则保持原画面 | 保留“查找外观相似目标”；可点“查看匹配片段”跳到主段 | 不是白车就必然匹配；不在未验证对象上随意加相似结果 |
| 约 5.60–6.50s | 主白色轿车进入有效可见段，四角框建立 | 外观匹配 → 结果输出点亮，出现“相似目标” | 生效时刻以标定为准；SUV 出画后必须结束其任何候选轨迹 |
| 6.50–9.50s | 主目标框连续跟随；可点选后暂停查看局部 | 参考小图与当前目标局部并列；提示“外观相似” | 不显示车牌、编造百分比分数或“确认同一车辆” |
| 9.50–10.00s | 停在经检查的结果帧 | “重播”“查看匹配片段” | 结果只保留这一可见段的证据 |

算法链可采用：视频输入 → 抽帧处理 → 车辆检测 → 外观特征 → 相似匹配 → 结果输出。节点名称是面向外行的展示文案，内部 ID 应与真实后端协议分开。

和自然语言一样，建议提供“查看匹配片段”直接跳到已校准的主段，避免访客先看数秒没有结果的车流。不要为凑时长在中段伪造目标框。

#### 6.3 匹配图交互

点击参考图可展开较大预览，点击结果可暂停并突出目标；关闭后回到原布局。静态版不提供看似已运行的任意文件上传分析：可以保留禁用态的“使用自己的图片”并标注“演示使用示例图”，或完全不显示该入口。

手机上参考图和结果排在视频下方，同排两小图或上下排列；不把参考图压在右下角遮住主白车。

### 7. 跟踪数据制作：这是实现任务，不是让 AI 猜坐标

#### 7.1 标定流程

1. 锁定展示媒体文件，记录 SHA256、宽高、帧率、时长、是否裁切、是否转码。三支原片每段约 240 帧，可以人工复核关键短段。
2. 逐帧看目标运动，先列出“有效可见段 / 部分遮挡段 / 不可见段 / 出画段”，再分配轨迹段 ID。先解决是谁和何时可见，再画框。
3. 对有效可见段标注紧贴目标的包围框。先每隔约 4–6 帧设置关键帧，快速运动、方向变化、遮挡边缘改成每帧或更密集关键帧；自动插值后逐帧回看。
4. 对行业 ROI 标定地面多边形与镜头运动。若自动平面跟踪失效，人工修正每段顶点；检查其与车道线、路面标志的相对位置稳定。
5. 对区外 → 区内过程计算并人工复核真实穿越时刻，保存事件引用的目标段 ID、区域 ID 与证据帧时刻。
6. 用同一播放器叠加数据，在 1× 和低速下检查。不要只验开始、中间、结束三帧。
7. 校验视频暂停、拖动、重播、换标签、换预设、缩放窗口后坐标、节点和结果一致，再按统一契约把分析文档的 `status` 从 `annotation-required` 改为 `ready`，填写 `reviewedAt` 与 `provenance`。不要另造第二套校准状态字段。

“标定”“跟踪”只是离线得到展示数据的方式。可以用离线工具辅助产生数据，再由人工校正；不要求首页首次访问时下载视觉模型、在手机浏览器里实时推理。

#### 7.2 建议数据字段

以下字段是演示数据的设计要求，具体 TypeScript 定义由技术架构文档统一；本文件不另建一套不兼容协议。

| 对象 | 必须记录的内容 |
| --- | --- |
| 媒体 | 媒体 ID、文件哈希、像素宽高、时长、帧率、版本、是否派生 |
| 校准状态 | 统一使用 `status: annotation-required / ready`；就绪时填写 `reviewedAt`，绑定校准媒体哈希 |
| 目标段 | ID、目标类别、有效起止时间、可见段内关键帧、归一化包围框；分析来源用统一 `provenance.kind: authored-demo / algorithm-output` |
| 区域 | ID、顶点顺序、逐时刻多边形或平面变换、地面锚定方式 |
| 事件 | ID、时间、目标段 ID、区域 ID、条件、结果文案、证据帧时刻 |
| 预设 | ID、工作流节点与连线、可执行能力、相关目标段 / 事件过滤条件 |
| 搜索示例 | 预设文字或参考图地址、展示标签、匹配结果段，不伪造分数 |

坐标基于视频源画面，以 `x / sourceWidth` 和 `y / sourceHeight` 归一化。视频内容区域和叠加层必须共享同一个显示矩形，黑边不能纳入归一化坐标范围。

关键帧插值仅发生在同一个已确认的可见轨迹段内。不可跨遮挡断点、不可跨切镜头、不可跨出画与再入画直接线性连接。任何没有可靠标定的时间都允许不画框，这是正确行为。

#### 7.3 媒体更换与校准失效

修改视频内容、裁切范围、播放速度、帧率、时长、镜头顺序或重新生成视频后，必须将跟踪标定标为失效，不继续套用旧结果。

仅做保持完整画幅、时间轴和像素对应关系的转码，也要更新媒体哈希并复查时间同步。未经复查不能自动把原件 `ready` 状态继承给派生版。使用有剪辑的短片时，应独立绑定数据版本，或显式记录源时间偏移；时间映射扩展遵照技术契约文档，不私自加入未定义的同名字段。

### 8. 手机与多分辨率：完整画面优先

- 能力视频保持各自原始宽高比：`1264 / 640`、`1280 / 720`、`1216 / 672`。不为统一外观强裁成竖版，也不把第一支和第三支拉伸成 16:9。
- 推荐视频宽度 100%，高度由比例确定；叠加 SVG 使用源宽高作为 viewBox，并与视频内容矩形一一对应。若外容器有留白，以实际内容矩形定位。
- 桌面算法链在视频下方展示当前任务实际节点；手机默认采用阶段摘要，点击展开后显示完整纵向节点列表，遵循《02_响应式与交互规范》。节点始终可读，不能把整条链缩到字只有 8px。
- 窄屏视频上的文字仅保留一个短目标标签及“功能演示”标识；搜索、参考图、结果说明、切换和按钮移动到画面下方。
- 原素材中的目标在小屏可能只剩十几像素。要提供“查看目标”暂停态局部预览或横屏 / 放大查看；局部预览标注来源帧，不能把放大插值称为增强识别精度。
- 点击目标框的有效触控范围可扩大，但视觉框仍贴合实际目标。鼠标悬停不是唯一入口，手机必须有同等点击按钮。
- 画面变宽变窄时线宽、标签字号按 CSS 像素控制，空间位置按源坐标缩放；不要让目标框线宽随 SVG 一起变得过粗或过细。

### 9. 播放性能与静态站实现边界

三支原件合计约 47.7 MB，自然语言单支约 32.2 MB，不能在首屏同时加载。初次仅准备当前场景的 poster 和必要元数据；接近能力区且当前标签激活后再加载对应视频。离开能力区或浏览器标签后台时暂停，不能在后台继续重复动效。

后续可以从原件制作保留画幅的网页播放派生版，原件不动；首轮编码目标是肉眼保持目标轮廓的同时降低传输体积，并通过电脑与手机实际检查决定码率，不承诺固定体积下必然清楚。所有视频默认静音，保留 `playsInline`；音轨可在另存派生版时移除，但不改原件。

渲染层从视频呈现时间取样，可使用 `requestVideoFrameCallback`，并提供基于 `requestAnimationFrame` + `currentTime` 的兼容路径；不能只依赖低频 `timeupdate` 事件移动目标框。播放状态单独处理 `waiting / seeking / paused / ended / error`。

不要用 React 组件顶层状态每帧重建整棵页面。逐帧位置更新留在绘制层或局部引用，业务状态只在节点、结果、预设等离散状态变化时更新。所有帧回调、观察器、监听器在标签卸载时清理。

素材未加载或损坏时保留 poster、简短错误和“重试”。尚未校准的数据不能随机补齐：先显示原画面和可操作的工作流；如需给设计评审演示粗位置，必须单独标明“位置示意，待校准”，不得把这种版本列为完成验收。

### 10. 静态演示与后端的交接

静态版的数据来源是本地 JSON / TypeScript fixtures。页面组件只消费统一的“媒体 + 工作流 + 轨迹 + 事件”结果，不在组件里硬编码“第 3 秒创建进入事件”。后续后端接入可以替换为文件结果、HTTP 分析结果或实时消息，组件不需要重写。

静态版必须可以从任意播放时间重建画面状态。事件显示采用按时间查询、按 ID 去重的方式；拖到事件前时撤销其呈现，拖到事件后时显示正确结果，不依赖“刚好经过某秒”的一次性定时回调。

所有当前结果标注数据来源为预设演示；真实后端尚未返回的置信度、跟踪 ID、车牌、模型名称、耗时、识别率不提供假值。真实 API 后续需要扩展的字段保留可选，不填造假的占位数字。

## 开发顺序、验收与缺口

本文件用于约束另一个 AI 的交付。先做一个能完整说明产品的首页，不以大批空页面或装饰动画代替核心交互。

### 1. 实施阶段

#### 阶段 A：建立可预览页面与稳定资源路径

读取全部设计文档、媒体清单和参考图。若在当前工程内开发，先确认 `website/package.json`、静态服务和已有页面路径，保持 HTML/CSS/ES Modules 架构，不擅自重建；若是独立空目录，采用技术文档给出的轻量静态工程方案。

建立导航、Hero、能力主舞台、精简下半页、页脚及 `/demo/` 最小页面；先用真实海报占位。三任务切换、导航锚点与预约跳页先可操作。Hero 纯背景缺失应列为明确缺项，不阻塞其他部分实现。

验收：320 px 与 1440 px 下结构都可读；核心按钮有效；无横向溢出、无死链；视频资源为包内路径，不引用开发者电脑的绝对路径。

#### 阶段 B：先完成行业场景纵向闭环

先对行业视频有效短段完成逐帧观察、目标与路面区域校准；将结果写入统一契约。实现“车辆检测／区域进入”两预设、六节点链、原始／分析／对照和事件回放。所有状态从媒体时间推导。

如果没有有效区外到区内的证据，不能伪造事件；应先修正预设区域或调整演示片段。未校准状态不能为了“看起来完成”输出随机方框。该阶段通过再扩展其他两个任务。

验收：暂停、重播、快进、倒退、改尺寸都不漂移；事件只在有效条件下出现；只检测模式不产生区域事件。

#### 阶段 C：自然语言与以图搜图

根据分镜选取有效短段。自然语言先支持一个明示预设；以图搜图先支持一个清晰参考图。实际制作参考图和轨迹时保持媒体来源一致；不同车辆／不同人不能共享假连续身份。

验收：三任务在视觉和行为上可区分；快速切换不残留另一任务的目标和结果；无需输入任意文本／上传任意文件就能体验能力；未提供的自由输入能力清楚限制。

#### 阶段 D：手机与动效精修

完成手机全画幅、操作外移、阶段摘要与完整链展开、目标局部查看。实现 Robotfolk 启发的同帧分析层显现、对照滑杆、节点与结果联动；减少动态模式与键盘体验同步完成。

验收：下面测试矩阵全部覆盖；避免只展示一张漂亮桌面截图。页面滚动始终自然可控。

#### 阶段 E：资源优化与交付

为大视频另存网页播放版本，保留原件、比例和时间映射。完善媒体加载失败、自动播放失败、离屏暂停。输出启动方式、页面地址、实际测试证据、未完成项及后续 API 接入说明。

除非用户另有明确要求，不部署、不购买模板、不提交真实预约、不上传视频给第三方服务。

### 4. 静态与接口边界验收

1. 内容、媒体、分析结果、预约操作各有明确数据提供层；页面组件不直接散落请求地址。
2. 切换到 `static-demo` 模式无需后端即可运行；任意输入、用户上传和真实预约提交默认不可用。
3. 准备一个映射适配器接口即可接入后端；演示 JSON 不强迫后端改成相同内部存储结构。
4. 媒体 ID、哈希、时间、坐标系和结果来源共同决定能否渲染；不同版本的数据不能静默混用。
5. 传入的文本按文本渲染；不把结果字段作为任意 HTML 注入。静态配置不包含 API key、私密 token 或个人联系方式。
6. 静态服务支持实际视频 Content-Type，需检查 Range／断点请求；文件与媒体配置可跟随基础路径部署。
7. 预约服务未配置时返回 `unavailable`；只有真实接口返回接收凭证才呈现已收到。
